# VIYO Security & Privacy Specification

**Application:** VIYO  
**Tagline:** See. Talk. Connect.  
**Classification:** Private & Confidential Family Media Platform

---

## 1. Authentication & Identity Protection

1. **Password Storage:** All passwords stored locally are salted and hashed using `bcrypt` (work factor 12). Plaintext passwords are never logged, cached, or transmitted in server logs.
2. **Token Security:** Short-lived JSON Web Tokens (JWT) signed with HS256 / RS256 algorithms. Tokens include standard claims (`sub`, `exp`, `iat`) and strict expiry validation.
3. **Firebase Token Verification:** Backend verifies Firebase ID tokens server-side using cryptographic verification. Client-supplied user identities are never trusted without cryptographic attestation.

---

## 2. Real-Time Media Security (WebRTC & LiveKit SFU)

1. **Selective Forwarding Unit (SFU) Isolation:** Media streams (audio, video, screen share) flow directly between clients and the LiveKit SFU over UDP/DTLS-SRTP encryption. Media frames never pass through FastAPI or relational databases.
2. **Short-Lived Media Tokens:** LiveKit access tokens generated by the backend are strictly scoped to a single `room_name`, specific participant identity, and granted exact permissions (`can_publish`, `can_subscribe`, `room_admin`). Tokens expire after 15 to 60 minutes.
3. **Zero Recording by Default:** Media recording is strictly disabled by default. If participant recording is ever enabled, explicit notification and consent flags are broadcast across all active participant sessions.
4. **No AI Training or Analytics on Family Data:** Family communication content, video streams, audio, and attachments are strictly isolated and never fed into AI models, advertising networks, or third-party telemetry.

---

## 3. Data Isolation & Privacy Controls

1. **Multi-Tenant Scoping:** Every user profile, contact, message, and call history record is strictly filtered by the authenticated user's ID at the SQL layer.
2. **Server-Side Privacy Evaluation:**
   - `privacy_last_seen`: When configured to `nobody` or `contacts_only`, non-contacts receive `null` values regardless of database state.
   - `privacy_calls`: Unapproved or blocked callers receive HTTP 403 Forbidden before any media room or ringing event is created.
3. **Attachment Sanitation:** Uploaded avatars and media files are checked for MIME type, file size limits (50MB ceiling), and stored with cryptographically random UUID filenames to prevent path traversal and arbitrary code execution.
